# Harness MVP 機能一覧

## 1. 本書の目的

本書は、[requirements.md](./requirements.md) で合意済みのHarness MVP要件を、実装・テストで参照しやすい機能単位に整理した一覧である。

本書の「確定」はMVP要件として確定していることを表し、実装済みであることは表さない。未確定の仕様は [open-issues.md](./open-issues.md) を参照する。

## 2. プロダクト概要

Harnessは、プロジェクトを解析し、技術スタックに適したAIコーディングエージェント向けのスキル、ルール、サブエージェントを初期配置するCLIである。

MVPでは次の2コマンドを提供する。

| コマンド | 概要 | 状態 |
| --- | --- | --- |
| `harness init` | プロジェクト解析、対話形式での選択、導入イメージの確認、初期配置を行う | MVP要件として確定 |
| `harness validate` | 配置済みの構成が対象AIエージェントの形式として妥当か検証する | MVP要件として確定 |

## 3. 機能一覧

| F-001 | リポジトリ解析 | 新規または既存プロジェクトの既知の構成ファイルとディレクトリ構成を読み取り専用で解析する | 確定 |

| F-004 | ロックファイル優先判定 | 依存関係を確定できるロックファイルがある場合、マニフェストの宣言より優先して判定する | 確定 |
| F-005 | モノレポ検出 | ワークスペース構成を解析し、単一アプリケーションとモノレポを識別する | 確定 |
| F-006 | 導入候補検出 | アプリケーション、サービス、ライブラリの候補と各ルートを検出する | 確定 |

| F-008 | 既存AI構成検出 | 既存の `.agents` および `.claude` 構成を検出する | 確定 |
| F-009 | 検出根拠表示 | 検出した項目と、その判定に使用した根拠を表示する | 確定 |
| F-010 | オフライン決定的解析 | LLM APIや外部通信を使わず、同一入力に対して同一結果を返すルールベース解析を行う | 確定 |

### 3.7 ファイル生成と安全性

| ID | 機能 | 概要 | 状態 |
| --- | --- | --- | --- |
| F-041 | 公式テンプレート生成 | Harnessに同梱した公式テンプレートだけを使用して構成ファイルを生成する | 確定 |
| F-042 | 対象別形式変換 | 共通テンプレートをCodexまたはClaude Codeの公式仕様に沿った形式へ、独立したアダプターで変換する | 確定 |
| F-043 | 対象別テンプレート差し替え | 共通形式から安全に変換できない場合、対象AIエージェント固有のテンプレートへ完全に差し替える | 確定 |
| F-044 | 変換エラー・警告 | 未定義変数、未対応項目、変換不能な設定を黙って破棄せず、エラーまたは警告として通知する | 確定 |
| F-045 | 一括書き込み | 複数候補への導入を一つの処理単位として実行する | 確定 |
| F-046 | 失敗時復旧 | 書き込み途中で失敗した場合、中途半端な導入状態を残さない | 確定 |
| F-047 | 既存ファイル保護 | 既存ファイルを暗黙に上書きせず、管理対象外のファイルを削除しない | 確定 |
| F-048 | アプリケーションコード保護 | スキル、ルール、サブエージェントの配置以外にアプリケーションコードを変更しない | 確定 |
| F-049 | 再現可能な生成 | 同一のテンプレート、入力、アダプターバージョンから同一の生成物を作成する | 確定 |
| F-050 | 独立利用可能な生成物 | 生成後はHarnessを常時利用せずに対象AIエージェントで利用でき、Git管理とユーザー編集を可能にする | 確定 |

## 4. 対応範囲

### 4.1 対応AIエージェント

| 対象 | 選択単位 |
| --- | --- |
| Codex | アプリケーション、サービス、ライブラリ候補ごと |
| Claude Code | アプリケーション、サービス、ライブラリ候補ごと |

### 4.2 対応技術スタック

| 分類 | 対象 |
| --- | --- |
| 言語・ランタイム | JavaScript、TypeScript、Node.js、PHP、Ruby、Java、Python |
| フロントエンド | React、Next.js |
| PHP | Laravel、Symfony |
| Ruby | Ruby on Rails |
| Java | Spring Boot |
| Python | Django、FastAPI |
| テスト | Vitest、Playwright |

### 4.3 対応環境

| 項目 | 対象 |
| --- | --- |
| OS | macOS、Linux、Windows |
| 実装言語 | TypeScript |
| 配布形式 | npmパッケージ |
| CLI表示言語 | 英語 |
| 公式テンプレート・生成物の本文 | 英語 |

## 5. 品質・運用要件

| ID | 要件 | 概要 | 状態 |
| --- | --- | --- | --- |
| Q-001 | クロスプラットフォーム | パス区切り、改行コード、ファイル権限、シンボリックリンクのOS差異を考慮する | 確定 |
| Q-002 | 公式仕様準拠 | 配置先、形式、メタデータ、命名規則、探索範囲、権限表現は対象製品の公式仕様を正とする | 確定 |
| Q-003 | 非対応機能の明示 | 対象製品に同等機能がない資産を独自形式で暗黙に生成しない | 確定 |
| Q-004 | テンプレート追跡可能性 | テンプレートにID、各種バージョン、適用条件、対応製品、出典、ライセンスを保持する | 確定 |
| Q-005 | 将来の多言語化 | テンプレート本文と言語情報を分離して管理する | 確定 |
| Q-006 | プライバシー | 解析と推薦をオフラインで実行し、プロジェクト情報を外部へ送信しない | 確定 |

## 7. MVP対象外

- 外部リポジトリ、URL、マーケットプレイスからのテンプレート取得
- テンプレートマーケットプレイス
- ユーザー独自テンプレートの登録
- GUI
- クラウド同期
- リモートでのAIエージェント実行
- ルート設定から子アプリケーションへの暗黙の継承
- 生成済みファイルの無断更新または削除
- すべての言語、フレームワーク、AIエージェントへの対応
